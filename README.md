# MLP A* Planner

## Project Topic

The topic of this project is the use of a simple MLP neural network as a replacement for a classical 2D occupancy map in an A* planner. The neural network learns to recognize whether a given map point is located in free or occupied space, and is then used during path planning.

Additionally, the project uses the gradient of the network output with respect to the input. The gradient makes it possible to determine whether a point is close to the boundary of an obstacle. Thanks to this, the planner can choose a path with a larger safety margin from walls.

---

## Project Goal

The goal of the project was to check whether a classical occupancy map can be partially replaced by a trained MLP network and whether gradient information from this network can improve the shape of the path generated by A*.

The project included:

- preparation of a 2D occupancy map,
- sampling of the map and creation of a dataset,
- training of a simple MLP network in PyTorch,
- use of the MLP as an occupancy model of the space,
- computation of the network gradient at a point,
- integration of the gradient into the A* cost function,
- comparison of classical A*, full MLP A*, and the path refinement variant,
- visualization of paths and visited cells in RViz.

---

## Implementation Method

The occupancy map was sampled in order to create a training dataset. The input to the network consists of point coordinates:

```text
x, y
```

The output is information about the occupancy of the point:

```text
0 - free space
1 - occupied space
```

The tests used a manually created map `map_large.pgm` with the size:

$$
120 \times 120 = 14400
$$

which gives a total of `14400` map cells.

The MLP network was trained to predict, based on the coordinates of a point, whether the point is located in free space or inside an obstacle. In this way, the MLP can act as an approximate continuous representation of the occupancy map.

The most important element of the project is the use of the MLP network gradient. The model can be treated as a function:

$$
f(x, y) \rightarrow [0, 1]
$$

where a value close to `0` means free space, and a value close to `1` means occupied space.

For each analyzed point, the gradient of the network output with respect to the input coordinates is computed:

$$
\nabla f(x, y) =
\left[
\frac{\partial f}{\partial x},
\frac{\partial f}{\partial y}
\right]
$$

Then the gradient norm is calculated:

$$
\left\| \nabla f(x, y) \right\|_2 =
\sqrt{
\left(\frac{\partial f}{\partial x}\right)^2 +
\left(\frac{\partial f}{\partial y}\right)^2
}
$$

In places far away from obstacle boundaries, the MLP function value changes slowly, so the gradient norm is small. Near the boundary between free and occupied space, the network value changes more rapidly, so the gradient norm increases.

This information was added to the transition cost in the A* algorithm. The gradient penalty has the following form:

$$
P_{grad}(x, y) =
\lambda_{grad} \cdot
\left\| \nabla f(x, y) \right\|_2
$$

The total cost of reaching the next point is calculated as:

$$
g_{new}(n) = g(current) + c(current, n) + P_{grad}(n)
$$

where:

- $g_{current}$ — the accumulated cost of reaching the current point,
- $c_{move}$ — the cost of moving to a neighboring cell,
- $P_{grad}(x, y)$ — an additional penalty for being close to an obstacle boundary,
- $\lambda_{grad}$ — a coefficient defining the influence of the gradient on planning cost.

Thanks to this, points located close to walls have a higher cost. The planner therefore chooses a path that not only leads to the goal but also keeps a larger distance from obstacles.

All A* variants used the Manhattan heuristic:

$$
h(x, y) =
|x_{goal} - x| + |y_{goal} - y|
$$

The evaluation function in A* has the standard form:

$$
F(x, y) = g(x, y) + h(x, y)
$$

In the classical variant, the cost $g(x, y)$ mainly depends on the path length. In the MLP variant, the cost $g(x, y)$ is additionally increased by the gradient penalty, which pushes the planned path away from obstacles.

Three variants were compared:

- `Classic A*` — classical A* using the occupancy map directly,
- `Full MLP A*` — A*, where both occupancy checking and the gradient penalty are based on the MLP model,
- `A* + MLP refine` — classical A* first computes a base path, and then the path is moved away from obstacles using information from the MLP.

## Results After 100 Program Runs

A special test script was used to compare the algorithms. It executed 100 program runs for the tested planner variants. In each run, metrics describing the algorithm behavior were saved: planning time, number of visited cells, and length of the resulting path in map cells.

Based on the collected data, metric statistics were calculated and plots of mean values and standard deviations were generated. The path planning time plot was shown on a logarithmic scale in order to clearly present the differences between classical A* and the variants using MLP.

Compared variants:

- `Classic A*`,
- `Full MLP A*`,
- `A* + MLP refine`.

## Planning Time

![Average planning time](results/time_mean_std.svg)

| Planner | Average planning time [s] |
|---|---:|
| Classic A* | 0.00576 |
| Full MLP A* | 0.604 |
| A* + MLP refine | 0.0640 |

Classical A* achieved the shortest planning time.  
`Full MLP A*` was the slowest because it performs network inference during execution and uses gradient information.  
`A* + MLP refine` works much faster than the full MLP variant because it first uses classical A* and only then performs path correction.

## Number of Visited Cells

![Average number of visited cells](results/visited_mean_std.svg)

|---|---:|
| Classic A* | 2762.64 |

`Classic A*` and `A* + MLP refine` visited the same average number of cells because the path refinement variant is based on the result of classical A*.  
`Full MLP A*` visited more cells because it includes an additional cost related to the gradient and searches for a path with a larger safety margin from obstacles.

## Path Length

![Average path length](results/path_cells_mean_std.svg)

| Planner | Average path length [cells] |
|---|---:|
| Classic A* | 127.91 |
| Full MLP A* | 137.31 |

Classical A* achieved the shortest average path.  
`Full MLP A*` generates a slightly longer path because it avoids passing close to obstacles.  
`A* + MLP refine` produced the longest average path because the correction moves path points away from walls, which makes the route deviate from the optimal path generated by classical A*.

## Conclusions

Classical A* is the fastest variant and generates the shortest path, but its path may pass close to obstacles because the algorithm mainly optimizes the cost of reaching the goal.

`Full MLP A*` finds a path successfully and maintains a better distance from walls because it uses a trained MLP model instead of a classical occupancy map. The model gradient is included in the cost function, so cells located close to obstacle boundaries receive a higher cost. Thanks to this, the planner chooses a safer route with a larger safety margin. The disadvantage of this variant is its significantly higher computation time.

`A* + MLP refine` works on average about 100 times faster than `Full MLP A*` because it does not perform full MLP-based search. It first uses classical A*, and only later shifts the path based on gradient information. The disadvantage of this approach is the greater path length, because the improvement consists of moving the already generated route away from obstacles rather than fully replanning it.

The path refinement variant depends on the original path generated by classical A*. When the environment changes, this may cause unnecessary loops or a less natural path shape. A version that included the history of the modified path was also tested, but because it moved the route even farther away from the optimal trajectory, it selected longer paths. For this reason, that variant was not chosen as the final one.

Ultimately, the project shows that an MLP can be used as an approximate representation of an occupancy map, and that the network gradient can effectively influence the planning of a safer path farther away from obstacles.

## Running Instructions

### 1. Go to the ROS 2 workspace

```bash
cd ~/ros2_ws
```

### 2. Clone the repository

```bash
cd src
git clone https://github.com/krukich/MiAPR-project.git mlp_astar_planner
cd ..
```

### 3. Install requirements

Make sure that PyTorch is installed:

```bash
pip install torch
```

### 4. Build the workspace

```bash
colcon build --symlink-install
```

### 5. Source the environment

```bash
source install/setup.bash
```

### 6. Run the project

```bash
ros2 launch mlp_astar_planner astar_comparision.launch.py
```
